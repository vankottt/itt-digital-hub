# ITT Agent Platform

One gateway, one tunnel, and one local runtime host every agent. Vercel stays the website. It does not call a model.

```text
Browser
→ https://ittdigitalhub.org          Vercel (pages, UI, content)
→ https://api.ittdigitalhub.org      Cloudflare Worker itt-agent-gateway
→ https://agent.ittdigitalhub.org    Cloudflare Tunnel itt-agent-hub
→ http://127.0.0.1:8788              Local Agent Hub
→ Agent registry
→ Agent
→ Model router / tool registry / local knowledge
```

The AI Act Assistant, Settlement Analyzer, and Pipe Thermal Analysis stay on their current routes. This platform does not replace them. The next step can move the AI Act Assistant onto the hub as one more agent.

## Boundaries

| Boundary | What crosses it |
| --- | --- |
| Browser → Worker | Versioned JSON only. No shared secret, no MCP, no model key. |
| Worker → Hub | HMAC over the raw body. The browser cannot call `agent.ittdigitalhub.org` and be accepted. |
| Hub → Agent | `Agent.handle(request, context)`. The hub does not know which model the agent uses. |
| Agent → tools / MCP | In-process only. `/mcp`, `/tools/list`, `/resources/list`, and `/prompts/list` are not routes. |

`workers.dev` is off, and the Worker config does not attach a route until `api.ittdigitalhub.org` is added on purpose. That avoids a second public hostname and avoids creating DNS by accident.

## Public API

`GET /v1/health`

```json
{ "status": "ok", "service": "itt-agent-gateway" }
```

`POST /v1/agents/:agentId/chat`

```json
{ "sessionId": "optional", "locale": "bg", "message": "user message", "history": [] }
```

`locale` defaults to `bg` and accepts `bg` or `en`. `history` is optional and is there so a later agent can keep a conversation without a provider-specific schema.

```json
{ "requestId": "...", "agentId": "...", "sessionId": "...", "answer": "..." }
```

Errors:

```json
{ "error": { "code": "AGENT_NOT_FOUND", "message": "Agent is not available.", "requestId": "..." } }
```

Responses do not include stacks, filesystem paths, internal hostnames, or secrets. Authentication failures inside the tunnel are returned to the browser as `UPSTREAM_UNAVAILABLE`.

CORS allows `https://ittdigitalhub.org` and `http://localhost:3000` unless `ALLOWED_ORIGINS` replaces that list. A request with no `Origin` is accepted so `curl` can smoke-test. A present `Origin` must match exactly. `*` is ignored.

## Worker → Hub authentication

The Worker signs every proxied body. The hub checks the signature before it parses JSON.

Headers:

- `X-ITT-Timestamp` — unix seconds
- `X-ITT-Signature` — lowercase hex HMAC-SHA256
- `X-ITT-Request-ID` — UUID generated by the Worker

Canonical bytes:

```text
timestamp + "." + METHOD + "." + path + "." + requestId + "." + raw body
```

Method, path, and request id are included so a captured body cannot be replayed against another route or under another request id. The comparison is constant-time: the Worker runtime uses `crypto.subtle.timingSafeEqual` when that API exists, and the Node hub uses the same byte-length scan otherwise. One implementation has to run in both places, so the hub does not depend on the Workers-only method.

Timestamps more than 300 seconds from the hub clock are rejected after the signature matches. A wrong signature is `INVALID_SIGNATURE` even if the timestamp is also old. There is no nonce store. A replay inside the 300-second window is possible. A later Turnstile, rate limit, or nonce check can sit in the Worker without a new backend. KV and Redis are not required for this first step.

The shared secret is `AGENT_HUB_SHARED_SECRET` on the Worker and `ITT_HUB_SHARED_SECRET` on the hub. It is not a `NEXT_PUBLIC_` variable and is not imported by the site. The published placeholder is refused when the gateway environment is `production` or the hub `NODE_ENV` is `production`.

The hub listens on `127.0.0.1` by default. The tunnel is the only intended path from the internet to that port. `/health` on the hub is unauthenticated and returns only status and service name. Chat requires a signature.

## Streaming

A successful hub response is passed through without buffering when its content type is `application/json` or `text/event-stream`. A later agent can stream SSE without a new gateway protocol. This step does not add a custom SSE stack. Error bodies are read only up to 8 KB so a bad upstream cannot be forwarded raw.

## Agents, models, tools, knowledge

```text
platform/agent-hub/agents/<id>/
  manifest.json
  handler.ts
  prompts/
  knowledge/
```

The manifest carries id, name, version, enabled, locales, and visibility, plus optional model policy, tool names, knowledge directory, limits, and a logging policy. `logging.conversation` is `none` or `metadata`. The hub logger does not accept conversation text. Secret-like fields are redacted if they are ever passed in.

`mock` is enabled and public. `example` is registered and disabled. An `internal` agent is hidden as `AGENT_NOT_FOUND`.

The model router calls the provider named on the request. It falls back only when that request names a fallback and the primary fails with a timeout, rate limit, network error, or provider error. A successful answer, including a short or uncertain one, does not call the fallback. `mock` returns a deterministic string. `openrouter` calls `https://openrouter.ai/api/v1/chat/completions` with Zero Data Retention and data collection denied. `gemini` calls the existing Google generateContent API when a server-side key is set. `local` and `openai` still refuse to run.

Tools are an in-process registry. `toolFromMcp` is the adapter an agent can use later. No business tool is registered.

Knowledge files stay on disk under the agent directory. Readers reject `..` paths. Nothing in this step embeds those files into a vector database.

## AI Act agent

`ai-act` is a public agent for `bg` and `en`. It reuses `src/content/ai-act-kit` for the system prompt, agent config, and legal sources. The two-question gate is a signed token returned in `state` and sent back as `clientState.gate`. A failed model call does not advance it. Leads are `POST /v1/agents/ai-act/actions/lead`. Kit checks use `POST /v1/agents/ai-act/actions/authorize`. The AI Act primary model is OpenRouter `z-ai/glm-5.3-flash`. Gemini `gemini-3.8-flash` is the hub fallback. Supabase, Resend, OpenRouter, and Gemini stay in the hub.
