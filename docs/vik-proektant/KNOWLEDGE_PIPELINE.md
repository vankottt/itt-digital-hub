## What is kept

Each chunk stores a stable id `vk1_<documentId>_a<article>_p<part>`, the document title, number, year, State Gazette reference, domains, section, article, and the completeness flags from the frontmatter (`safe_for_textual_rag`, `safe_for_numeric_answer`, `content_completeness`, `missing_content_types`). Page numbers are not invented. The extracted text does not carry reliable page numbers, so `page` is null.

## Indexing

`buildCorpus()` reads `Tools/WSS - AI Asistant/Вик Асистен - Знание/knowledge/**/*.md`, skips `README.md`, splits on `Чл.` headings, and splits an article longer than 1,800 characters. Search text includes the document title so an ordinance name can rank an article inside it. Identical normalized chunk text is marked `duplicateOf` and is not returned as a second source. The current collection has no exact duplicate chunks. Historical source files noted in the knowledge manifest are not indexed as separate documents.

Questionable documents are classified, not deleted. Documents with `safe_for_numeric_answer: false` or `requires_manual_verification: true` stay searchable, and the tool result carries those flags. Formula text that still says it was not extracted stays in the chunk so the skill can refuse to reconstruct it.

## Search

Search is lexical: token stemming, inverse document frequency, title overlap, and an exact article filter. A request for an article that does not exist returns no hits. Category filters must match a domain present in the corpus. Results are capped at 8 excerpts of at most 700 characters. `get_vik_reference` returns one chunk and short neighbouring text.

No embedding service is called. Supabase in this project is used for the CMS and AI Act leads, not for a vector index.

## Updating

1. Add or replace a markdown file under `knowledge/` using the existing frontmatter.
2. Do not edit V1 retrieval code as part of that update.
3. Run `npm run vik-proektant:audit`.
4. Run `npx vitest run tests/vik-proektant`.
5. Restart the Next.js server or the local MCP process. The index is built in memory on first use.

There is no separate vector rebuild.
